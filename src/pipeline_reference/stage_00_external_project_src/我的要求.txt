推荐基础配置：



```yaml

stage: sft

finetuning_type: lora

lora_target: all

lora_rank: 32 或 64

bf16: true
```

```yaml

```



不要盲目增加 epoch，优先优化任务构造、负样本、推理流程和后处理。



## 5. 实验路线



### test1：baseline 复现



```text

目录：ours_zzl_test1

任务：ENTITY + RELATION

比例：ENTITY 50% / RELATION 50%

推理：ENTITY → RELATION → normalize → eval

作用：作为所有实验对照组

```



### test2：加入 JOINT



```text

目录：ours_zzl_test2

任务：ENTITY + RELATION + JOINT

比例：ENTITY 35% / RELATION 35% / JOINT 30%

```



JOINT 输出：



```json

{

  "entities": [{"text": "...", "label": "..."}],

  "relations": [

    {"head": "...", "head_label": "...", "relation": "...", "tail": "...", "tail_label": "..."}

  ]

}

```



观察 JOINT 是否补充漏抽关系，是否引入幻觉关系，JSON 是否稳定。



### test3：加入 RELATION_CLASSIFY



```text

目录：ours_zzl_test3

任务：ENTITY + RELATION + RELATION_CLASSIFY

```



新增任务：



```text

[TASK=RELATION_CLASSIFY]

TEXT + HEAD + TAIL → NONE/AFF/CON/HAS/LOI/OCI/USE

```



构造方式：



```text

正样本：gold relations

负样本：同文本共现但无关系的实体 pair

正负比例：1:2 或 1:3

```



推理时先抽实体，再构造 pair 分类，过滤 NONE，并与生成式关系合并。



重点观察 RE precision、RE recall、方向错误和 NONE 阈值。



### test4：加入 ENTITY_VERIFY



```text

目录：ours_zzl_test4

任务：ENTITY + ENTITY_VERIFY + RELATION

```



新增任务：



```text

[TASK=ENTITY_VERIFY]

TEXT + candidate entity → corrected span + label / NONE

```



训练样本包括：



```text

gold entity

边界扰动实体

普通词假阳性

模型误抽实体

```



推理时先宽松生成实体候选，再逐个验证和修正。



重点观察 NER precision、边界错误和泛指词误报。



### test5：完整多任务组合



```text

目录：ours_zzl_test5

任务：ENTITY + ENTITY_VERIFY + RELATION + RELATION_CLASSIFY + JOINT

```



初始比例：



```text

ENTITY 25%

ENTITY_VERIFY 20%

RELATION 20%

RELATION_CLASSIFY 25%

JOINT 10%

```



推理流程：



```text

高召回 ENTITY

→ ENTITY_VERIFY

→ 构造实体 pair

→ RELATION_CLASSIFY

→ RELATION 生成式补充

→ JOINT 补充

→ 合并、去重、投票、normalize、eval

```



这是优先级最高的完整方案。



### test6：困难负样本增强



```text

目录：ours_zzl_test6

```



基于当前最好模型或 baseline，收集：



```text

误识别普通词

错误边界 span

共现但无关系实体 pair

混淆关系

方向错误关系

```



构造成：



```text

ENTITY_VERIFY 的 NONE 样本

RELATION_CLASSIFY 的 NONE 样本

关系方向纠错样本

```



重点观察 precision、RE false positive 和 JSON 稳定性。



### test7：检索感知训练增强



```text

目录：ours_zzl_test7

```



为每条数据构造不同 SRAG 版本：



```text

高相似正例

标签互补示例

无关系负例

容易误导近邻

无检索版本

```



比较：



```text

无检索

固定 top-k 检索

多样化检索

检索 + 投票

```



重点观察 SRAG 是否真实提升，以及是否复制示例答案。



## 6. 统一评测要求



所有实验必须使用同一套 normalize/eval 流程。



必须统计：



```text

NER Precision / Recall / F1

RE Precision / Recall / F1

Overall score

JSON parse success rate

Invalid JSON count

Empty prediction count

Average entities per sample

Average relations per sample

```



非法 JSON 要记录原始输出，再做可控修复。报告中同时记录修复前后 JSON 成功率。禁止用 dev gold 修复预测内容。



## 7. 投票与验证



候选实体/关系需记录来源：



```text

ENTITY generation

ENTITY_VERIFY

RELATION generation

RELATION_CLASSIFY

JOINT

SRAG round id

```



初始保留规则：



```text

实体：>=2 票保留；verify 通过可 1 票保留

关系：classify 非 NONE 优先保留；生成式关系需要 >=2 票

```



可在 dev 上搜索类别自适应阈值，但不能使用 test label。



关系可做双向验证：



```text

TEXT + HEAD + TAIL → relation / NONE

TEXT + TAIL + HEAD → relation / NONE

```



若双向验证导致 recall 明显下降，仅在高误报类别启用。

## 9. 多方法合并训练



如果某条路线满足以下任一条件，则进入合并实验：



```text

Overall 高于 baseline

RE F1 明显提升

NER precision 或 recall 明显提升

JSON 成功率不下降

虽然总分未提升，但改善了关键错误类型

```



合并实验命名：



```text

ours_zzl_test8

ours_zzl_test9

ours_zzl_test10

...

```



优先组合：



```text

test3 + test4：

ENTITY + ENTITY_VERIFY + RELATION + RELATION_CLASSIFY



test2 + test3：

ENTITY + RELATION + JOINT + RELATION_CLASSIFY



test4 + test6：

强化 ENTITY_VERIFY + hard negative entity correction



test3 + test6：

强化 RELATION_CLASSIFY + NONE hard negatives



test2 + test3 + test4：

ENTITY + ENTITY_VERIFY + RELATION + RELATION_CLASSIFY + JOINT

```



根据 dev 结果动态调整比例。



推荐比例：



```text

RE 是短板：

ENTITY 20% / ENTITY_VERIFY 15% / RELATION 20% / RELATION_CLASSIFY 35% / JOINT 10%



NER 边界是短板：

ENTITY 25% / ENTITY_VERIFY 35% / RELATION 15% / RELATION_CLASSIFY 15% / JOINT 10%



漏抽关系严重：

ENTITY 20% / ENTITY_VERIFY 15% / RELATION 25% / RELATION_CLASSIFY 25% / JOINT 15%



JSON 不稳定：

减少 JOINT，优先 ENTITY + ENTITY_VERIFY + RELATION_CLASSIFY

```



合并后必须重新训练同一个 checkpoint。最终仍只能依赖一个 checkpoint。



## 10. 迭代策略



每完成一个实验，立即：



```text

1. dev 推理

2. normalize

3. eval

4. 更新 summary

5. 根据结果决定下一步

```



没有 dev 结果的实验不算完成。



失败路线及时停止，包括：



```text

JSON 成功率显著下降

NER/RE F1 明显低于 baseline

训练 loss 异常

大量空输出

```



优先投入时间到：



```text

RELATION_CLASSIFY

ENTITY_VERIFY

困难负样本

高召回生成 + 同模型验证

优秀路线合并训练

```



不要把大量时间浪费在单纯增加 epoch 或重复全参数训练上。
